GearPlay Store
Guide de déploiement complet
Environnement Docker · Prisma · PostgreSQL · Node.js
Version 1.0 · Août 2026 · Document technique pas-à-pas
Objectif de ce document. Vous guider, étape par étape, pour transformer le site GearPlay (actuellement en localStorage) en une vraie boutique en ligne avec base de données PostgreSQL, API backend et déploiement Docker. Aucune connaissance préalable de Docker ou Prisma n'est supposée : chaque commande est expliquée.

1. Vue d'ensemble de l'architecture

Le site final se compose de trois briques qui tournent ensemble :

BriqueRôleTechnologie
FrontendLes pages HTML/CSS/JS déjà livréesFichiers statiques (Netlify / Nginx)
Backend APIExpose les produits, commandes, authNode.js + Express + Prisma
Base de donnéesStocke produits, commandes, adminsPostgreSQL (dans Docker)

Docker permet de lancer la base de données et le backend avec une seule commande, sans rien installer manuellement sur votre machine (à part Docker lui-même).

Résultat final : vous tapez docker compose up et tout le site tourne en local sur http://localhost:8080. Pour la mise en ligne, on pousse la même configuration sur un serveur.

3. Structure du projet backend

Créez un nouveau dossier gearplay-backend/ à côté du dossier gearplay/ (le frontend). Organisez-le ainsi :

gearplay-backend/ ├── prisma/ │ ├── schema.prisma # définition de la base de données │ └── seed.js # données initiales (les 6 produits) ├── src/ │ ├── index.js # serveur Express (point d'entrée) │ ├── routes/ │ │ ├── products.js # CRUD produits │ │ ├── orders.js # commandes │ │ ├── auth.js # connexion admin (JWT) │ │ └── stripe.js # paiement │ └── middleware/ │ └── auth.js # vérification du token admin ├── .env # variables secrètes ├── Dockerfile # image du backend ├── docker-compose.yml # orchestration (DB + backend + front) └── package.json

4. Initialiser le projet Node

Ouvrez un terminal dans gearplay-backend/ et lancez :

# Créer le package.json
npm init -y

# Installer les dépendances
npm install express cors dotenv @prisma/client bcryptjs jsonwebtoken stripe
npm install --save-dev prisma nodemon

# Initialiser Prisma
npx prisma init

La dernière commande crée le dossier prisma/ et un fichier .env.

5. Définir la base de données avec Prisma

Prisma est un « ORM » : vous décrivez vos tables en langage simple, et il génère la base et le code d'accès. Remplacez le contenu de prisma/schema.prisma par :

generator client {
  provider = "prisma-client-js"
}
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Product {
  id          String   @id
  name        String
  brand       String
  cat         String
  model       String
  priceN      Float
  oldN        Float?
  off         Int      @default(0)
  rating      Float    @default(0)
  reviews     Int      @default(0)
  stockN      Int      @default(0)
  inStock     Boolean  @default(true)
  description String?
  viewer      String   @default("canvas")
  embedUrl    String?
  colors      Json
  specs       Json
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}

model Order {
  id         String   @id
  createdAt  DateTime @default(now())
  email      String
  name       String?
  address    Json?
  lines      Json
  subtotal   Float
  discount   Float    @default(0)
  shipping   Float    @default(0)
  total      Float
  status     String   @default("confirmée")
  stripePi   String?
  promoCode  String?
}

model Admin {
  id           Int    @id @default(autoincrement())
  username     String @unique
  passwordHash String
}

6. Configurer Docker

Docker Compose lance PostgreSQL + le backend ensemble. Créez docker-compose.yml :

services:
  # --- Base de données PostgreSQL ---
  db:
    image: postgres:16
    restart: always
    environment:
      POSTGRES_USER: gearplay
      POSTGRES_PASSWORD: motdepasse_secret
      POSTGRES_DB: gearplay
    ports:
      - "5432:5432"
    volumes:
      - dbdata:/var/lib/postgresql/data

  # --- Backend API Node ---
  api:
    build: .
    restart: always
    depends_on:
      - db
    environment:
      DATABASE_URL: "postgresql://gearplay:motdepasse_secret@db:5432/gearplay"
      JWT_SECRET: "changez_cette_chaine"
      STRIPE_SECRET_KEY: "sk_live_votre_cle"
    ports:
      - "3000:3000"

  # --- Frontend (Nginx sert les fichiers statiques) ---
  web:
    image: nginx:alpine
    restart: always
    ports:
      - "8080:80"
    volumes:
      - ../gearplay:/usr/share/nginx/html:ro

volumes:
  dbdata:

Puis créez le Dockerfile (image du backend) :

FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npx prisma generate
EXPOSE 3000
CMD ["sh", "-c", "npx prisma migrate deploy && node src/index.js"]

7. Le serveur Express (src/index.js)

const express = require('express');
const cors = require('cors');
require('dotenv').config();
const app = express();
app.use(cors());
app.use(express.json());

app.use('/api/products', require('./routes/products'));
app.use('/api/orders', require('./routes/orders'));
app.use('/api/auth', require('./routes/auth'));
app.use('/api/stripe', require('./routes/stripe'));

app.listen(3000, () => console.log('API sur http://localhost:3000'));

Exemple : routes/products.js (le CRUD complet)

const router = require('express').Router();
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();
const auth = require('../middleware/auth');

// Lister (public)
router.get('/', async (req, res) => res.json(await prisma.product.findMany()));

// Détail (public)
router.get('/:id', async (req, res) => {
  const p = await prisma.product.findUnique({ where:{ id:req.params.id }});
  p ? res.json(p) : res.status(404).json({ error:'Introuvable' });
});

// Créer (admin)
router.post('/', auth, async (req, res) =>
  res.json(await prisma.product.create({ data:req.body })));

// Modifier (admin)
router.put('/:id', auth, async (req, res) =>
  res.json(await prisma.product.update({ where:{ id:req.params.id }, data:req.body })));

// Supprimer (admin)
router.delete('/:id', auth, async (req, res) => {
  await prisma.product.delete({ where:{ id:req.params.id }});
  res.json({ ok:true });
});

module.exports = router;

8. Lancer le tout étape clé

Dans le dossier gearplay-backend/, exécutez dans l'ordre :

1
Démarrer la base + le backend + le front :
docker compose up -d
2
Créer les tables dans la base (première fois seulement) :
docker compose exec api npx prisma migrate dev --name init
3
Injecter les données initiales (les 6 produits) :
docker compose exec api node prisma/seed.js
4
Ouvrir le site : http://localhost:8080 — l'API tourne sur http://localhost:3000.
Commandes utiles au quotidien :
• docker compose up -d → démarrer
• docker compose down → arrêter
• docker compose logs -f api → voir les logs du backend
• docker compose exec api npx prisma studio → interface visuelle de la base (sur port 5555)

9. Connecter le frontend au backend

Actuellement, js/db.js lit dans localStorage. Il faut le faire lire dans l'API. Remplacez les fonctions par des appels fetch :

const API = 'http://localhost:3000/api'; // en prod : https://api.gearplay.fr/api

async function dbGet(){
  const r = await fetch(API + '/products');
  return r.json();
}
async function dbUpsert(p, token){
  const method = p._isNew ? 'POST' : 'PUT';
  const url = p._isNew ? API+'/products' : API+'/products/'+p.id;
  await fetch(url, { method, headers:{
    'Content-Type':'application/json', 'Authorization':'Bearer '+token
  }, body: JSON.stringify(p) });
}
Attention : les pages qui appellent dbGet() doivent devenir async (utiliser await dbGet()). C'est le principal travail d'adaptation du frontend. Un développeur le fait en 1-2 jours.

10. Mise en ligne (production)

ÉlémentOù l'hébergerComment
FrontendNetlify / VercelGlisser-déposer le dossier gearplay/
Backend + DBRailway / RenderConnecter le repo Git, ils détectent le docker-compose
Nom de domaineOVH / GandiPointer gearplay.fr → Netlify, api.gearplay.fr → Railway
SSL (HTTPS)AutomatiqueFourni gratuitement par Netlify et Railway

Étapes de publication

  1. Pousser le code sur un dépôt GitHub (frontend + backend).
  2. Sur Railway : « New Project » → « Deploy from GitHub » → sélectionner le repo backend. Railway crée automatiquement la base PostgreSQL et lance le conteneur.
  3. Renseigner les variables d'environnement sur Railway (voir section 11).
  4. Sur Netlify : glisser-déposer gearplay/ (ou connecter le repo). Modifier la constante API dans db.js pour pointer vers l'URL Railway.
  5. Acheter le domaine, le brancher sur Netlify (le SSL s'active seul).
  6. Configurer Stripe en mode « live » et coller la clé pk_live_ dans paiement.html.
